> 문서 기준일: 2026-10-20 · 용도: 농장 로컬 Edge의 역할, 공개 배포 정보와 설치·업데이트 지원 조건 안내

Edge는 농장에 설치하는 **로컬 엔드서버이자 현장 판단의 중심**입니다. 농장주·허용된 현장 작업자는 Edge 사용자 앱으로 해당 온실의 환경·장치·경보를 확인하고, 권한과 현재 안전 조건이 허용하는 업무를 수행합니다. IoT·PLC 연결·관측·실제 I/O는 Controller가 담당하고, Cloud는 고객/Edge 관리와 허용된 외부 가공 정보의 중앙 전달을 담당합니다.

새 기준의 기능·페이지는 구현·검사를 위한 계획입니다. 새 환경관리 앱·모든 데이터 격리/전환·업데이트 화면이 이미 구현·검증되었다는 뜻은 아닙니다. 문서 정비 다음에는 UI 템플릿/컴포넌트 레퍼런스를 비교·선정하고 최소 구현·검사를 진행합니다. 특정 작물의 재배·예측·방제 기능과 장치 모델은 별도 검토·지원 범위입니다.

## 2. 사용자 업무와 앱 간 책임

| 주요 흐름 | Edge가 맡을 내용 | 확인할 경계 |
| --- | --- | --- |
| 온실 상황 확인 | 현재 선택한 해당 온실의 환경·장치·경보·연결·자료 최신성을 한 화면에서 파악 | 한 Edge가 한 온실만 관리한다고 고정하지 않음. 미관측·미설치·불명은 실제 정상값/0과 구분 |
| 경보 원인 확인 | 관련 관측·이력·장치/Controller 상태와 자료 출처를 연결 | 화면·cache가 현장 원본/안전 판단을 대신하지 않음 |
| 허용된 업무 수행 | 사용자·대상·현재 상태를 확인하고 판단·명령·결과를 기록 | UI 버튼/사용자 요청이 직접 장치 I/O가 아님. Controller 실행 검사와 실제 결과 확인 필요 |
| 외부 정보 활용 | Cloud가 전달한 자기 농장/허용 공용 자료의 출처·시각·유효성·적합성 확인 | 가공 정보와 실제 센서 관측을 구분. 오래된/미지원 자료로 업무 조건을 임의 충족하지 않음 |
| 현장 기록·허용 Cloud 교환 | 상세 관측과 현장 원본을 유지하고, 요약/주요 이벤트·경보·관리 상태 전달을 기본으로 계획 | 실제 항목·주기·보존·단절 용량은 별도 결정/검증. 모든 원시 관측을 기본 공개·공유하지 않음 |
| 업데이트·현장 인계 | 해당 현장에 허용된 안내·현재/목표 버전·실제 적용/검사·실패/복구 결과를 확인 | Cloud 전달·다운로드·설치 종료·업무 복구는 서로 다른 단계 |

현장 업무 판단은 Edge가 소유합니다. Cloud 관리 요청은 Edge의 현재 허용·권한·업무/안전 조건을 통과해야 하며 Cloud 성공 응답만으로 현장 적용 완료를 뜻하지 않습니다. Controller 정비 클라이언트도 Edge 판단을 우회하는 새 상시 제어 경로가 아닙니다.

## 3. 클라이언트·서버·Core 산출물

| 구분 | 대상·목적 | 릴리즈에서 따로 확인할 것 |
| --- | --- | --- |
| Edge 서버 실행부 | 농장 로컬 서버의 관측/원본 저장·판단·허용 명령·Cloud/Controller 교환 | 실행 환경·DB/파일·계약, 현장 구성·연결, 중단·이행·백업/복원·기동/업무 검사 |
| Edge 환경관리 클라이언트 | 기존 Edge 서버에 접속하는 농장주/현장 사용자 데스크톱·후속 모바일 앱 | OS/CPU·서버 접속/인증, 실제 Core 소비 버전, 단절/재개·권한/대상 전환·종료 |
| Core 소비 자산 | Edge가 사용하는 공통 구동·규격·UI/템플릿·교환 지원 | 포함 버전·호환 조건과 로컬 사용 가능 범위. 별도 Core 상시 서버 연결을 필수로 가정하지 않음 |

기존 서버·장치 실행부는 유지하고 클라이언트는 공통 기반 언어의 원본으로 **Windows·Linux부터**, Android·iOS·macOS는 후속 개발합니다. 프레임워크·UI 라이브러리·패키징·최소 OS/CPU·Linux 검증 배포판은 선정과 실제 검사 후 안내합니다. 모든 OS 버전 지원을 약속하지 않으며 클라이언트 종료가 서버·Controller 종료를 뜻하지 않습니다.

향후 컨테이너 이미지·설치 파일·패키지 등 여러 산출물을 함께 제공한다면 실제 릴리즈가 지정한 집합 식별과 각 자산의 불변 식별자를 사용합니다. 이미지 개수·파일 이름·설치 경로를 이 README에서 미리 고정하지 않으며 서로 다른 검증 집합을 임의로 섞지 않습니다.

## 4. 릴리즈 확인·설치·업데이트 순서

1. Edge 릴리즈에서 정식/사전 배포·철회/지원 상태·변경 영향·알려진 제한을 확인하고 서버와 환경관리 클라이언트 자산을 구분합니다.
2. 현재 현장의 Edge 서버/클라이언트·Controller·Cloud·Core 소비 버전과 계약·DB 형식, 장치/profile 조건을 해당 지원 조합과 비교합니다. 버전 숫자가 같다는 이유만으로 호환성을 판단하지 않습니다.
3. 해당 현장의 권한·관측·DB·장치 상태와 허용 작업, 작업 중단 영향·담당자·현장 확인·백업/복원 가능성을 검토합니다. 물리 I/O가 연관된 변경은 현장별 안전 조건을 먼저 확인합니다.
4. 승인된 안내에 지정된 자산만 내려받고 정확한 자산의 체크섬·서명·신뢰 가능한 발행자/출처를 검증합니다. 존재하지 않는 파일·명령·주소·키를 추측해 실행하지 않습니다.
5. 정해진 순서대로 적용하고 서버 기동·현재 계정/대상 권한·관측/DB·Controller 연결·Cloud 교환·해당 업무를 확인합니다. 실제 OS의 새 클라이언트 접속·권한 거절·단절/재개·종료도 별도 확인합니다.
6. 설치된 버전·실제 검사/미실행 범위·미완료/불명 결과·남은 제한을 기록합니다. 지원 확인 전까지 미검증 조합을 정상 지원으로 표시하지 않습니다.

릴리즈에는 공개 허용 source 식별·서버/클라이언트·Core 소비 버전, 자산별 대상/식별·신뢰 검증, 실제 검사 조합과 알려진 제한, 이행·중단·복구·설치 후 확인 방법을 연결합니다. GitHub 자동 `Source code` ZIP은 이 공개 저장소의 태그 내용이며 Edge 제품 설치본이 아닙니다. [GitHub 공식 릴리즈 문서](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

## 6. 농장 격리·공개 범위·지원

기본은 **A 농장이 A 농장 정보와 서버가 공유를 허용한 공용 정보만 받는 것**입니다. 관측·설정·일지·파일·개별 모델 결과·알림/캐시도 해당 범위를 따르며, 같은 기상 자료를 받는 다른 농장의 정보/명단을 받지 않습니다. 계정·농장·온실 전환은 이전 대상 화면·응답·구독을 새 대상으로 섞지 않도록 설계합니다. 실제 기능 구현/검사 완료는 별도 증거로 확인합니다.

공개 게시 대상은 승인된 일반 안내·릴리즈 설명·허용 산출물입니다. 비공개 기준 문서 원문·내부 PR/CI 로그·고객/농장/장치 식별정보·관측/설정/원문 로그·내부 주소·자격정보·개인키·검증하지 않은 바이너리/임의 체크섬은 게시하지 않습니다.

지원 시 공개 가능한 앱/서버/클라이언트 버전·OS·발생 시각·민감정보를 제거한 증상·마지막 확인 상태·수행한 조치를 준비합니다. 지정된 비공개 지원 창구가 있으면 그 경로로 전달하고, 현장 원문 자료는 공개 이슈에 붙이지 않습니다. 아직 정하지 않은 공개 연락처·응답 시간·장치 지원 수치를 임의로 안내하지 않습니다.

## 7. 유지관리

새 기능은 관련 사용자 경로와 실패/복구의 E2E·계약·회귀 검사에 연결합니다. Cloud·Controller와 이전/새 버전 혼용은 실제로 실행한 조합·환경만 지원 근거로 기록하고, 미실행을 통과로 채우지 않습니다. 릴리즈·이 README·Cloud의 허용된 현장 버전 안내가 같은 자산/지원 상태를 가리키도록 관리합니다.

운영 피드백에는 실패 원인·실제 복구·남은 제한·다음 계획에서 재사용할 검사를 남깁니다. 문서 최신화가 새 설치 파일 게시·자동 업데이트·현장 배포를 뜻하지 않으며 실제 게시·설치/운영 적용은 별도 검토·승인을 거칩니다.
